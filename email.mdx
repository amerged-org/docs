title: "Transactional email"
description: "Set a sender domain, follow DKIM verification and verify delivery."
---

Managed transactional email requires Paid access and a sender domain for the project. Use a sender subdomain where appropriate to preserve your existing inbox setup:

```sh
ohmyhost mail domain set --project "$PROJECT_ID" --domain mail.example.com --idempotency-key "$MAIL_REQUEST_KEY" --json
ohmyhost mail domain status --project "$PROJECT_ID" --json
```

Apply the exact DNS records returned by the service, through [Cloudflare authorization or manual DNS](/domains). Preserve mailbox MX records.

## While verification is pending

The status includes the current observation and next action. Follow `next_check_after_seconds`, normally 3600. A stored configuration receipt is not a new provider observation; use the actual status response to decide what remains.

Do not recreate the sender or repeat correct records because DKIM is still propagating. Resume the original deployment after its dependency becomes ready.

## Verify application delivery

Use `createTransactionalMailClient` from `@ohmyhost/customer-runtime/mail` in server-side application code. A mail-enabled deployment supplies a private `OHMYHOST_MAIL_GATEWAY` Service Binding alongside the gateway URL, project ID and secret key. Resolve these values from your hosted framework request context or Worker `env`:

```ts
import { createTransactionalMailClient } from "@ohmyhost/customer-runtime/mail";

const mail = createTransactionalMailClient({
  endpoint: env.OHMYHOST_MAIL_GATEWAY_URL,
  key: env.OHMYHOST_MAIL_KEY,
  projectId: env.OHMYHOST_PROJECT_ID,
  fetch: (request) => env.OHMYHOST_MAIL_GATEWAY.fetch(request),
});
```

The Service Binding is an object, not a `process.env` string. The gateway URL supplies the request origin; it is not a public endpoint. Missing bindings are configuration errors. Do not retry through a different transport, disable placement or loosen egress rules to hide the failure. Managed mail works independently of your application's auth provider or database.

Keep the idempotency key and message unchanged when checking or retrying an uncertain send. `accepted` means accepted for sending; it does not establish inbox delivery. Project permissions, sending limits and credit checks still apply.

Sender verification, account sending availability and deployment completion are separate checks. Send a real transactional message through your application's supported runtime and verify receipt before claiming email works.

If `verification_issue` reports a missing tenant association, report the operation through [feedback](/feedback); that is platform provisioning, not a request for the customer to guess new DNS records. Respect suppression and sending limits returned by the service.
