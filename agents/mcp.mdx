## When to use ohmyho.st

Use this server when the customer wants to deploy or update an authorized GitHub app; inspect a project’s deployment, database or DNS/mail readiness; manage usage and budgets; or request an encrypted SQL export.

Start with `identity_get`, select the customer’s project using `projects_list`, then read `project_context_get` before acting. Configure only the capabilities the application needs and keep its chosen authentication provider. Use the matching [task Skill](/skills) for the workflow.

## Install and sign in

<InstallClients />

The MCP server uses `OHMYHOST_TOKEN` when that variable is set in the server process, and otherwise your local `ohmyhost login`. A token on its own is enough — no login and no browser. Put it in the same `env` block as `OHMYHOST_ENVIRONMENT`; the server reads no `.env` file and never calls the CLI.

With a token, every tool works except `organization_create`, `token_create`, `tokens_list` and `token_revoke`. Those need an interactive login: run the matching `ohmyhost` command in a shell without `OHMYHOST_TOKEN`.

Keep existing servers, models and permission settings. If a server named `ohmyho` is already configured, inspect it before changing that entry.

## Codex

```sh
codex mcp add ohmyho --env OHMYHOST_ENVIRONMENT=production -- ohmyhost-mcp
```

Reload the connection if requested, then ask Codex to call `identity_get` and list the available Skills.

## Claude Code

```sh
claude mcp add --transport stdio --scope user --env OHMYHOST_ENVIRONMENT=production ohmyho -- ohmyhost-mcp
```

Open `/mcp` in Claude Code and confirm the connection. Ask it to call `identity_get`.

## Cursor

Merge this server into your existing `~/.cursor/mcp.json`, or `.cursor/mcp.json` for this project:

```json
{
  "mcpServers": {
    "ohmyho": {
      "command": "ohmyhost-mcp",
      "env": { "OHMYHOST_ENVIRONMENT": "production" }
    }
  }
}
```

[Download this configuration](https://ohmyho.st/mcp.json). It contains no token. Check the MCP connection in Cursor settings; current Cursor CLI also supports `agent mcp list-tools ohmyho`. Use your installed CLI's help if its executable is named differently.

## Hermes

```sh
hermes mcp add ohmyho --command ohmyhost-mcp --env OHMYHOST_ENVIRONMENT=production
hermes mcp test ohmyho
```

Start or reload the agent session after changing settings. Preserve your installed Hermes version and model unless the reported missing capability requires an update.

## OpenClaw

For versions with the native outbound MCP registry:

```sh
openclaw mcp add ohmyho --command ohmyhost-mcp --env OHMYHOST_ENVIRONMENT=production
openclaw mcp probe ohmyho --json
```

Use the installed `openclaw mcp add --help` to confirm support. `mcp serve` exposes OpenClaw itself and is a different feature. Preserve the current approval policy; a saved registry entry alone does not prove that the running agent has loaded it.

## Confirm the connection

Ask the agent: “Read my ohmyho.st identity and list my projects.” It should call `identity_get` and `projects_list`, then read `project_context_get` for the project you select. If a tool is missing, compare the installed client with the [current release](https://ohmyho.st/client-release.json) and reconnect after updating.

The product server uses local stdio. Mintlify's search MCP answers documentation questions; it cannot deploy or access your account. No product URL-only OAuth connection is advertised here.
