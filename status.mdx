---
title: "Read deployment status"
description: "Follow the accepted operation and inspect the actual application heads."
---

```sh
ohmyhost project context --project "$PROJECT_ID" --json
ohmyhost project status --project "$PROJECT_ID" --json
ohmyhost operation get "$OPERATION_ID" --json
```

Use the operation ID returned by the mutation. `queued` or `running` means work remains; `succeeded`, `failed` and `cancelled` are terminal. Project status supplies actual environments, deployment heads and URLs.

## Observe the next step

During a deployment, `progress.phase` distinguishes building, publishing and waiting for mail. Follow `progress.next_poll_after_seconds` and the returned suggested action. Read sender or domain status when that dependency is pending.

CLI `--wait` can reach its own timeout without cancelling the server operation. Read the same operation afterward. Never submit another deployment just to get a status update.

For a live event stream:

```sh
ohmyhost logs "$OPERATION_ID" --follow --json
```

MCP `operation_logs` returns a bounded snapshot. Use `operation_get` for current completion rather than assuming the snapshot waits until done.

## Verify success

An operation marked succeeded must still produce the requested outcome. Open a private Dev access link when needed and test the real application, or read back the changed domain, budget or compute settings.
